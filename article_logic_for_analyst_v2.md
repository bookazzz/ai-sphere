# Логика производства SEO-контента для AI-Sphere v2

## Конвейер производства

```
Сбор семантики
→ очистка мусора
→ нормализация брендов
→ определение сущности, задачи, модификаторов
→ определение интента
→ предварительная тематическая группировка
→ SERP-кластеризация (пересечение топ-10)
→ сопоставление с существующими URL
→ проверка каннибализации
→ решение по странице
→ определение типа контента
→ SEO-бриф
→ сбор и проверка фактов
→ написание
→ проверка SEO, фактов, ссылок, CTA
→ build и deploy
→ контроль индексации и позиций
```

## 1. Типы страниц и шаблоны

Каждому типу — свой шаблон.

### Страница модели
```
Что это за модель
Кто разработал
Актуальные версии (с защитой: 4.6 → не 46)
Возможности
Контекстное окно
Работа с русским языком
Стоимость
API
Ограничения
Доступность в AI-Sphere
CTA: Попробовать {модель}
```

### Инструмент
```
Рабочая форма / назначение
Что можно сделать
Пример результата
Пошаговое использование
Стоимость запроса
Ограничения
Связанные инструменты
CTA: Открыть {инструмент}
```

### Сравнение
```
Краткий вывод
Таблица различий:
  - текст / код / документы / изображения
  - скорость
  - цена
  - версии
Какую модель выбрать под задачу
CTA: Сравнить самому / Запустить {модель}
```

### Инструкция / Гайд
```
Для кого этот гайд
Пошаговый план
Скриншоты / примеры
Типичные ошибки
Советы
CTA: Начать использовать
```

### Новость
```
Что произошло
Когда и кто объявил
Что изменилось
Цена и доступность
Чем отличается от прошлой версии
Почему это важно
Официальные источники
CTA: Попробовать в AI-Sphere
```

### Рейтинг / Подборка
```
Критерии отбора
Краткая таблица
Лучший вариант по сценариям
Подробный разбор участников
Методология
CTA: Выбрать модель
```

**Правило:** Hermes сначала определяет `content_type`, и только потом выбирает структуру.

## 2. Правило URL: один подтверждённый интент = один целевой URL

Один тематический кластер может породить несколько страниц:

```
/models/deepseek/               — обзор модели
/deepseek-online/                — продуктовая страница
/deepseek-api/                   — API и цены
/kak-polzovatsya-deepseek/       — инструкция
/deepseek-vs-chatgpt/            — сравнение
/news/deepseek-r2-release/       — новость
```

Несколько узких кластеров могут закрываться одной страницей:

```
ChatGPT онлайн
ChatGPT на русском
ChatGPT бесплатно
ChatGPT без регистрации
     ↓
одна страница /chatgpt-online/ с секциями
```

## 3. Решения по странице (действия)

Перед созданием — проверка каннибализации:

1. Существует ли страница под этот интент?
2. Какие запросы она закрывает?
3. Совпадает ли её выдача с новым кластером?
4. Можно обновить вместо создания?

Решение (одно из):

| Действие | Когда |
|----------|-------|
| `create_page` | Новый качественный интент, страницы нет |
| `update_existing` | Страница есть, нужно обновить контент |
| `merge_into_existing` | Запрос закрывается существующей страницей |
| `merge_into_parent` | Отдельная страница не нужна, часть родительской |
| `split_cluster` | Кластер слишком большой, интенты разные |
| `use_as_secondary` | Запрос как вторичная семантика |
| `serp_check` | Не хватает данных для решения |
| `discard` | Не создавать |

## 4. H1, Title, Description

### H1
Не по максимальной частотности, а по:
- основному интенту
- естественности формулировки
- содержанию страницы
- соответствию продукту
- составу выдачи

Плохо: `DeepSeek — нейросеть | ai-sphere.ru`
Хорошо: `DeepSeek: обзор нейросети, модели и возможности`

Бренд сайта — в `<title>`, не в H1.

### Title
Отражает одну главную ценность страницы, не перечисление ключей.

Плохо: `DeepSeek онлайн, бесплатно, на русском, без регистрации | AI-Sphere`
Хорошо: `DeepSeek онлайн на русском — попробовать нейросеть | AI-Sphere`

### Description
Краткий ответ, не перечисление преимуществ.

Плохо: `Бесплатно, быстро, удобно, онлайн, без регистрации и ограничений.`
Хорошо: `Разбираем возможности DeepSeek, доступные модели, цены и ограничения. Модель можно запустить на русском через AI-Sphere.`

⚠ Не обещать «бесплатно» / «без ограничений», если продукт этого не даёт.

## 5. Объём текста

Не фиксированный 800–1500 слов, а ориентир по типу:

| Тип | Объём |
|-----|-------|
| Короткая новость | 400–800 слов |
| Инструмент | 500–1200 |
| Страница модели | 900–1800 |
| Сравнение | 1200–2500 |
| Инструкция | 1200–3000 |

**Главное правило:** Закончить, когда интент полностью закрыт. Не добавлять текст ради объёма.

---

## 6. Требования к качеству

Вместо «уникальность 90%+» (бесполезно):

- Текст написан с нуля
- Не повторяет композицию конкурента
- Факты подтверждены первичными источниками
- Есть собственная таблица или сравнение
- Есть практические примеры
- Указаны ограничения
- Понятный CTA
- Основной вопрос закрыт до первого скролла

## 7. Первый абзац

Без вступлений. Сразу суть.

Плохо: `В современном мире нейросети становятся всё популярнее...`
Хорошо: `DeepSeek — это китайская LLM с открытой моделью и контекстом 1M токенов.`

## 8. Факты и источники

Порядок приоритета:
1. Официальный сайт разработчика
2. Документация
3. Официальная страница цен
4. Model card
5. GitHub
6. Независимые тесты
7. СМИ — только для контекста

Для каждой страницы хранить:
- `datePublished`
- `dateModified`
- `lastFactCheck`
- `sourceUrls`

**Hermes запрещено придумывать:**
- цены
- benchmark
- версии
- доступность в России
- функции
- наличие модели в AI-Sphere

## 9. CTA

Ссылки на Ozon убрать. Основные CTA для AI-Sphere:

- `Попробовать {модель}`
- `Сравнить с {модель}`
- `Загрузить документ`
- `Создать презентацию`
- `Открыть AI-чат`
- `Зарегистрироваться`

CTA ведёт на запуск модели, рабочий инструмент, сравнение, страницу цены, регистрацию, связанный обзор или официальный источник.

## 10. Перелинковка

Не «внутри кластера» (противоречие), а граф сущности:

```
DeepSeek
├── обзор (/deepseek-chat/)
├── онлайн-доступ (/deepseek-online/)
├── инструкция (/kak-polzovatsya-deepseek/)
├── цены API (/deepseek-api/)
├── сравнения (/deepseek-vs-chatgpt/)
└── новости (/news/deepseek-r2-release/)
```

Правила:
- Новость → ссылается на постоянную страницу модели
- Модель → ссылается на инструкцию и сравнения
- Сравнение → ссылается на рабочий запуск обеих моделей

## 11. Приоритет страниц

Не по сырой частотности, а по совокупности:

```
Релевантность продукту
× коммерческий потенциал
× частотность
× достижимость
× качество текущей выдачи
× возможность дать уникальную ценность
× вероятность регистрации
```

Запрос `нейросеть для анализа PDF` может быть ценнее `GPT`, потому что пользователь уже знает задачу.

Тип воронки — по намерению, а не по вопросительной форме:

## 13. Обновление контента

Обновление запускается при изменении:
- официальной документации
- версии модели
- тарифов
- контекстного окна
- названия версии
- доступности API
- возможностей продукта
- наличия модели в AI-Sphere
- условий использования

OpenRouter — источник для цен API, но не единственный.

## 14. Техническая архитектура

Файлы контента (не TSX-страницы):

```
src/content/seo/models/deepseek.ts
src/content/seo/tools/generator-teksta.ts
src/content/seo/guides/deepseek-v-rossii.ts
src/content/seo/comparisons/deepseek-vs-chatgpt.ts
src/content/news/deepseek-r2.ts
```

Маршрутизация: `src/app/(seo)/[slug]/` — универсальный шаблон.

Build/deploy — отдельный процесс, НЕ в редакторском промте.

---

## 15. Структура промта для Hermes по этапам

Документ разделён на четыре самостоятельные инструкции:

1. **Семантика и кластеризация** — сбор, очистка, сущность/интент, SERP, решение по странице
2. **SEO-бриф и архитектура** — тип страницы, шаблон, H1/Title/Description, URL, CTA
3. **Написание и фактчекинг** — факты, источники, структура, объём, качество
4. **Build и deploy** — сборка, scp, chmod, sitemap

---

## 16. Защита от ошибок

- Версии моделей: `4.6`, `3.5`, `2.5 Pro`, `5.3 Codex`, `4o`, `o3-mini` — защищать от нормализации
- Не удалять точки из версий
- Проверять факты по первоисточникам
- Не добавлять длину ради длины
- Не обещать бесплатный доступ, если его нет
- Не использовать один шаблон для всех типов страниц
